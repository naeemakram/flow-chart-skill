How Playwright Test runs your tests

What happens between npx playwright test and the report, traced from the microsoft/playwright source (the test runner alone is about 27,000 lines of TypeScript). Read it to understand flaky retries, timeouts that fire in hooks, and why a beforeAll can run more than once.

As built: microsoft/playwright main at commit 820620c (1 Nov 2026). Worker restart, retry placement, hook timeouts and beforeAll re-runs checked by probe against @playwright/test 1.64.1.

The whole run

The runner process never executes your tests. It loads and filters them, splits them into groups, and hands each group to a worker process. Projects that depend on other projects wait in later phases.

One test inside a worker

Each test gets a timeout (30 seconds by default). Not every hook spends from it: beforeEach and test fixtures do, beforeAll and afterAll get their own, and the after-hooks get an extra allowance.

Defaults that surprise testers

Defaults worth knowing
IDSettingDefaultWhat it means for you
Test timeout30 sCovers beforeEach, test fixtures and the test body together. A slow login in beforeEach eats your test's time.
expect timeout5 sPer waiting assertion, still inside the 30 s test timeout.
Retries0A flaky test fails the run. Set retries in CI, and watch the flaky count.
Workers50% of CPU coresA 2-core CI runner gets 1 worker. Set workers explicitly if your CI machine differs from your laptop.
fullyParallelfalseTests in one file run one after another in one worker. Only files run in parallel.
Retry strategyimmediateThe retry runs straight away in a fresh worker, together with the rest of the file. 'isolated' runs retries one at a time at the end instead.
After a failureNew workerbeforeAll and worker-scoped fixtures run again for the rest of the file.
globalTimeout0 (none)A hung run is only stopped by your CI's own job timeout.
maxFailures0 (no limit)Every test runs even when the app is clearly down. Set it to fail fast in CI.
