How requests sends one HTTP call

What happens between requests.get(url) and the Response you get back, traced from the psf/requests source. The library is about 6,400 lines of Python; this page is the part you need to reason about timeouts, redirects, credentials and connection reuse.

As built: psf/requests main at commit 3c7baaa (26 Oct 2026). Timeout and redirect behaviour checked by probe against requests 2.34.2.

The life of one call

Every call goes through a Session, even requests.get(): it creates a throwaway session for that one call. The session merges your arguments with its own settings and the environment, hands the request to an adapter chosen by URL prefix, and the adapter hands it to urllib3.

Following a redirect

Redirects are where requests quietly changes your request. It follows browsers rather than the letter of the RFC, and it protects credentials when the host changes.

Where each setting can come from

A per-call argument beats a Session attribute, which beats the environment. But not every setting exists at every level, and the gaps explain some common bugs.
